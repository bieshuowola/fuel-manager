# 燃油与续航管理工具

移动端静态 PWA，无账户、无服务器数据库。默认记录「仪表总里程 + 实际加油升数」；忘记升数时，可选择金额补录，并从 [今日油价](https://bieshuowola.github.io/today-fuel-price/) 的公开数据接口读取福建宁德 92 号汽油参考价。实际成交单价有优惠时应手动更正，公告过旧会显示提醒。

## 动态加权油耗模型

1. **满油法有效周期**：只有已知两次加满、期间全部补油升数可靠、至少 80 km，且实测油耗在合理范围内的周期参与学习。周期耗油量为期间所有补油升数之和（包括最后一次加满），除以总里程差 × 100。金额估算周期不进入高可信度学习，但仍用于虚拟油量账本。
2. **平均油耗**：启动参考值 3.92 L/100 km 来自历史极限续航和标称油箱容量，并非精确实测；首次少量有效样本保留弱先验。使用最近最多 8 期，行驶里程越长参考权重越高（但设上限），近期权重越高；对孤立离群值降低权重，但不会直接屏蔽可信的高油耗周期。
3. **安全油耗**：独立结合近期峰值、波动和平均油耗计算。可信的高耗油样本立即提高安全油耗；下降最多约 0.30 L/100 km／新增有效周期，避免因短期省油过快放松安全边界。样本不足时保留初始保守参考 4.5 L/100 km。高耗油周期仍可能出现，模型不能预知未来骑行方式。
4. **安全剩余油量**：以每段记录时已经掌握的安全油耗扣油，额外扣除金额估算记录的油量不确定性；再扣除设置中的预留油量（默认 2 L），换算为保守可骑公里数。安全账本触底仅表示应加油，不能当作传感器故障；普通油量账本异常才提示校准。
5. **账本一致性**：历史记录不使用后来学到的油耗倒推过去。每次真正加满油时把两个虚拟账本重新校准到参考容量。若数据缺失、长期未更新里程或加油液面标准不一致，误差仍会累积；数值只截至最后录入的仪表总里程。

## 重要使用说明

- 仪表总里程和加油升数无法自动读取；工具也没有后台 GPS 或里程提醒，安全续航不是实时数据。
- 油箱参考容量与安全预留量可在设置中调整；首次只有**实际加满**后才能初始化。
- 所有里程、加油记录和设置存于浏览器 localStorage，不会上传到公开 GitHub 仓库；支持 JSON 备份和恢复。
- GitHub Pages 使用 `main` / `(root)`，静态资源包括 `index.html`、`sw.js`、`manifest.webmanifest`、`icon.svg`。
- 浏览器的 file://、其他域名和这个 Pages 域名是独立存储；从旧入口迁移需要先导出 JSON，再导入新版。离线时仅能使用此前缓存的参考油价。
- 运行回归测试：`node --test tests/model.test.js` 或 `node tests/model.test.js`。

**估算不能代替真实油量检测。遇到油量异常、遗漏记录或预计接近安全线，应尽早加油并加满重新校准。**
