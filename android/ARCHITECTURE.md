# Android v0.1 architecture and acceptance contract

The root website, model, storage key `nk250_fuel_manager_v1`, version-1 JSON and CSS are immutable. `prepare_web.py` generates APK-only assets with narrow, asserted adapter insertion points. The original replay/learning functions remain authoritative: 12.5 L, 3.92 reference, 4.5 initial safety, 2 L reserve, 40 km alert, 80 km full-cycle minimum are read from the website, not duplicated as a native fuel model.

WebViewAssetLoader HTTPS local origin → original web ledger → original replay → transient GPS mileage event in a cloned in-memory ledger → original animation/render. The transient event is never saved, exported as a real ODO, or used as a full-fill anchor. Forms/history use the true ledger. A real mileage/refuel event reconciles all pending distance once at the trusted input boundary. GPS never creates a full-fill learning sample. Unbounded gaps or unconfirmed transport suppress both displayed numerical fuel and safe range; known accepted distance is preserved for diagnostics, never interpolated across gaps.

Native AtomicFile JSON → accepted metre totals, pending-trip segments, quality counters, true-ODO reconciliation audit, monitoring preferences and fuel mirror. Main thread serializes service and bridge mutations. No precise trajectory is persisted. Process/boot interruption marks unknown; no invisible GPS restart. Activity Recognition transitions only offer a notification to open a location foreground service; they never establish motorcycle identity. Without Play services the manual vehicle-confirmed foreground mode remains functional using LocationManager fused/GNSS. Recording survives closing the Activity; no wake-lock, accessibility or background-start workaround.

Acceptance: website git blobs unchanged; deterministic GPS fixtures and calibration tests; original and projection regression tests; Debug assemble plus lint; offline browser flows incl. backup/animations; SHA-256 APK. Device-only claims (lockscreen, OriginOS background retention, Android 16, OCR quality, battery, 3%/5% distance targets) remain unverified until actual rides. No background-location permission: transitions prompt the user to start from visible Activity. OCR is bundled on-device Latin digit recognition with explicit ODO region selection and mandatory manual confirmation; TRIP/speed/clock ambiguity is never automatically accepted.
